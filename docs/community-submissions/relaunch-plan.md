# Relaunch plan

## Day 0 — make the repository convert

- Push the README, real demo, new social assets, screenshot manifest, and npm
  metadata.
- Update the GitHub description and topics.
- Set `assets/social-preview.png` as the repository social preview.
- Rewrite the current GitHub Release around the user problem and attach the
  demo in the body.

Success check: a logged-out visitor can explain that every descendant answer
can fork again at any depth—without affecting its parent, siblings, or the main
task—after watching the GIF once, and reaches the install command before
implementation detail.

## Day 1 — enter DSH-native discovery

- Publish the prepared official **Show Your Plugins!** discussion.
- Submit the `awesome-dsh-plugin/awesome-dsh-plugin` entry.
- Submit the ZeroPoint curated-list entry if its current category structure
  still matches the draft.
- Verify that the npm page shows the new description after the next package
  release; do not publish a docs-only version solely to bump recency.

## Day 3 — tell the developer story

- Post the Reddit version in one relevant community after checking its current
  self-promotion rules.
- Share the short Discord version in an appropriate DSH plugin channel.
- Answer questions with the session-boundary and read-only details already in
  the README; do not turn replies into a feature roadmap.

## Day 7 — one concise follow-up

- Post the X version with the GIF.
- Check traffic sources, README-to-npm clicks, installs, issues, and the most
  common misunderstanding.
- Make at most one documentation correction if the same misunderstanding
  appears repeatedly. Do not add a new feature to manufacture another launch.

## Stop conditions

Do not keep rewriting the hero because of normal day-to-day traffic variance.
Wait at least a week before judging the positioning, and prefer evidence from
questions, install attempts, and retention over raw impressions.
